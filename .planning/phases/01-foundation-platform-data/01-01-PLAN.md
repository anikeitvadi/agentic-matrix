  <action>
Create Velite configuration for type-safe platform content:

1. Create velite.config.ts with:
   - Root: 'content'
   - Output: { data: '.velite', assets: 'public/static', clean: true }
   - Collections:
     - platforms:
       - pattern: 'platforms/**/*.mdx'
       - schema with:
         - slug: s.slug('platforms')
         - title: s.string().max(99)
         - description: s.string().max(999)
         - lastVerified: s.isodate() (for timestamp requirement)
         - tier: s.enum(['enterprise-os', 'ipaas-agent', 'developer-first', 'vertical'])
         - capabilities: s.array(s.string())
         - pricing: s.object({ model: s.string(), details: s.string() })
         - officialDocs: s.string().url()
         - pricingPage: s.string().url().optional()
         - body: s.mdx()
     - policies:
       - pattern: 'policies/**/*.mdx'
       - schema with: slug, title, lastUpdated, body

2. Create content/platforms/ directory with .gitkeep

3. Create content/policies/ directory with .gitkeep

4. Update tsconfig.json to include ".velite" in paths:
   - Add: ".velite": [".velite"]
   - This enables: import { platforms } from '.velite'

5. Verify Velite generates types by running npm run dev (Velite runs at startup)

IMPORTANT:
- Use s.isodate() for lastVerified (returns Date-compatible string)
- The tier field maps to the competitive landscape tiers in PROJECT.md
- Schema should be strict enough to catch content errors at build time
  </action>
