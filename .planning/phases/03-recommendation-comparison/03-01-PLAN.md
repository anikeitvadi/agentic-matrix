<task type="auto">
  <name>Task 1: Create scoring type definitions</name>
  <files>lib/scoring/types.ts</files>
  <action>
Create TypeScript types for the scoring engine:

1. `Criterion` interface:
   - name: string
   - weight: number (0-1, must sum to 1.0 across all criteria)
   - value: number (raw value before normalization)
   - normalizedValue: number (0-1 after min-max normalization)
   - higherIsBetter: boolean (false for price, timeline)

2. `AuditEntry` interface:
   - criterionName: string
   - rawValue: number | string
   - normalizedValue: number
   - weight: number
   - weightedScore: number (weight * normalizedValue)
   - reasoning: string (human-readable explanation)

3. `PlatformScore` interface:
   - platformId: string (matches platform slug)
   - platformName: string
   - totalScore: number (0-100)
   - criteriaScores: Criterion[]
   - auditTrail: AuditEntry[]

4. `WeightConfig` interface:
   - integrationFit: number
   - complianceMatch: number
   - budgetFit: number
   - featureMatch: number
   - stackCompatibility: number
   (All must sum to 1.0)

5. `ScoringContext` interface:
   - allPlatforms: Platform[] (from velite)
   - userAssessment: Record<string, unknown> (from form)
   - weightConfig: WeightConfig

Export all types with JSDoc comments explaining purpose and constraints.
  </action>
  <verify>TypeScript compiles: `npx tsc lib/scoring/types.ts --noEmit`</verify>
  <done>All 5 interfaces exported and documented. WeightConfig constraint (sum to 1.0) noted in JSDoc.</done>

<task type="auto">
  <name>Task 2: Create normalization utilities</name>
  <files>lib/scoring/normalize.ts</files>
  <action>
Create normalization functions following research patterns:

1. `normalizeMinMax(value: number, min: number, max: number, higherIsBetter: boolean = true): number`
   - Handle edge case: if max === min, return 0.5 (neutral score)
   - Formula: (value - min) / (max - min)
   - If higherIsBetter is false, invert: 1 - normalized
   - Clamp result to 0-1 range

2. `normalizeCriterion(platforms: Array<{id: string, value: number}>, higherIsBetter: boolean): Map<string, number>`
   - Extract min/max from all platform values
   - Return Map of platformId -> normalized value
   - Handle empty array edge case (return empty Map)

3. Export a `CRITERION_DIRECTIONS` constant mapping criterion names to higherIsBetter boolean:
   - integrationFit: true (more integrations = better)
   - complianceMatch: true (more compliance = better)
   - budgetFit: false (lower price = better, invert this)
   - featureMatch: true (more features = better)
   - stackCompatibility: true (more compatibility = better)

Add unit test comments showing expected behavior for edge cases.
  </action>
  <verify>TypeScript compiles: `npx tsc lib/scoring/normalize.ts --noEmit`</verify>
  <done>Both functions exported. Edge cases handled: max=min returns 0.5, empty array returns empty Map. CRITERION_DIRECTIONS exported.</done>
